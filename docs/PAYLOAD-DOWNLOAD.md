# Payload 下载排查与回归

## 3.1.24 批次收尾

用户 2026-10-27 的录屏显示，累计下载接近 384 MiB 和 512 MiB 时，活动连接逐步减少，速度降到 KB/s，随后重新提速。代码中的远程输入窗口最大为 128 MiB：原实现收到完整窗口后才开始下一窗口，只处理连续无数据的尾段，持续少量回传可以一直保持空闲计时器活跃。

现在使用两个持久 Qt 读取线程提前衔接相邻窗口，共享所有分区的总连接预算。当前输入缓存与待取窗口合计最多两个；消费者切换窗口时先释放旧缓存。操作顺序、跨操作合并、倒序与不连续源范围均沿用原有校验规则。

窗口中一半以上槽位完成后，剩余请求如持续至少 3 秒、最近一秒速度不足同窗口已完成请求平均速度的八分之一且预计还需超过 2 秒，会提前恢复一次。比较基准按每个已完成请求的实际传输时长计算，不把等待全局连接名额的时间混入。持续无数据 3 秒仍会恢复。该机制不限制下载速率，也不会把用户设置的 512 连接改成较低上限。

有稳定 ETag/Last-Modified 时恢复请求补读余下范围；没有稳定标识则整块重读。最多三次尝试，保留精确 Range、总长度、文件版本和 SHA256 检查。两个读取线程各自持有显式 NoProxy 的网络管理器，取消或异常时一起停止并完成清理。

## 可复现样本

`MigrationTests::payloadTricklingTailsDoNotBlockNextWindow` 在本机模拟服务器中让每个窗口第一段先返回一半数据，此后每 50 毫秒只传 256 字节。服务器持续有数据，空闲超时不会触发。测试同时检查：

- 前一窗口慢尾段尚未断开时，已经请求下一窗口的数据。
- 有文件标识的补读、无文件标识的整块重读均成功，输出内容完全一致。
- 512 连接设置跨两个 128 MiB 窗口完成，活动连接不超出设置。
- 既有取消、损坏 SHA256、顺序/倒序/间隔操作、连接复用和并发截止时间回归继续通过。

修改前的小样本到 12 秒取消仍未完成。该模拟不等于公网 OTA 性能测试；当前没有用户录屏所用的完整下载地址，不能据此声称该源已完整下载或保证实际带宽。
